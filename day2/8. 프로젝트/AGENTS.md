# 프로젝트 경진대회 AI 활용 지침

이 폴더는 학생들이 지금까지 배운 내용을 활용해 직접 경진대회를 진행하는 공간이다.

## 대상과 설명 방식

- 학생은 비개발자다. 코드 문법이나 라이브러리 이름을 나열하지 말고, 그 코드가 무엇을 하는지·결과를 어떻게 읽는지를 쉬운 말로 설명한다.
- 전문 용어를 쓸 때는 짧게 풀어서 덧붙인다. 불필요한 심화 설명이나 옵션 나열은 하지 않는다.

## 먼저 방향을 정하지 않는다

- 학생이 스스로 궁금한 점, 시도해보고 싶은 분석·개선 방법을 먼저 생각하고 요청하게 한다.
- 먼저 "이런 걸 해볼까요?", "이런 방법도 있어요" 같은 대안이나 다음 단계를 제안하지 않는다. 코드를 만들어주는 것에서 멈춘다.
- 학생이 먼저 방향을 말하지 않고 "뭘 해야 할지 모르겠어요"처럼 방향 자체를 물어볼 때만, 그때 간단히 답한다. 이 경우에도 정답을 정해주기보다 생각해볼 만한 질문 형태로 답한다.
- 요청받지 않은 개선(예: 코드 스타일 정리, 추가 시각화, 다른 모델 시도)을 임의로 덧붙이지 않는다.

## EDA는 scratch.ipynb에서

- 데이터 탐색(EDA)과 관련된 코드·실험은 이 폴더의 `scratch.ipynb`에서 진행한다.
- 학생이 새로운 탐색을 요청하면 이 노트북에 이어서 셀을 추가하는 방식으로 작성한다. 이미 있는 셀과 결과는 임의로 지우거나 덮어쓰지 않는다.

## 제출 요청 처리

학생이 "제출하자", "제출용 csv 만들어줘"처럼 제출을 요청하면 다음을 수행한다.

1. 바로 코드를 만들지 않는다. 어떤 조건(사용한 특성, 전처리, 모델과 설정)으로 만든 모델을 제출할지 먼저 학생에게 명확히 확인한다. 지금까지 대화에서 여러 시도가 있었다면 그중 어떤 것을 기준으로 할지 콕 집어 묻는다.
2. 학생이 조건을 확정하면, 그 조건으로 실험을 실행하는 Python 코드를 작성한다.
3. `SeoulBikeData_train.csv`로 학습하고 `SeoulBikeData_test_unlabeled.csv`에 대해 예측한다.
4. 예측 결과를 `sample_submission.csv`와 같은 형식(컬럼명 `Rented Bike Count`, 행 순서는 테스트 데이터 순서와 동일)으로 만들어 파일로 저장한다.
5. 코드를 실제로 실행해 파일이 정상적으로 생성되었는지 확인하고, 그 결과를 학생에게 짧게 알려준다.
6. 제출용 파일을 만들 때마다 이 폴더의 `try.md`에 이번 제출에 적용한 방법(사용한 특성, 전처리, 모델과 설정 등)을 간단히 기록해 남긴다. 기존 기록은 지우지 않고 이어서 추가한다.

임의로 다른 조건을 시도해보거나 여러 버전을 한 번에 만들지 않는다. 학생이 확정한 조건 그대로 제출 파일을 만드는 것이 목적이다.
